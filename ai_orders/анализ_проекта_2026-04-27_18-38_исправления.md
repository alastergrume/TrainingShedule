## 1. Логика формирования расписания

### 1.1. Архитектура формирования расписания
Проект использует двухуровневую систему формирования расписания:

1. **Шаблоны тренировок (Training)**: 
   - Определяют повторяющиеся тренировки (например, "Силовая тренировка" в понедельник в 09:00)
   - Содержат: название, тип (персональная/коммерческая/базовая), день недели (0-6), время начала, продолжительность
   - Являются шаблонами для генерации конкретных занятий

2. **Конкретные занятия (ScheduleEntry)**:
   - Создаются на основе шаблонов для конкретных дат
   - Содержат: дату проведения, время начала/окончания, связь с шаблоном
   - Могут быть отменены (is_cancelled)

### 1.3. Управление расписанием администратором
Администратор может:
1. **Создавать/редактировать/удалять шаблоны тренировок** через API
2. **Создавать одноразовые занятия** (ScheduleEntry) вне шаблона
3. **Отменять конкретные занятия** с уведомлением записавшихся пользователей
4. **Редактировать время/дату конкретного занятия**

### 1.4. Публикация расписания
1. Расписание генерируется автоматически каждое воскресенье (Celery Beat)
2. Форматируется в читаемый вид с использованием `ScheduleFormatter`
3. Публикуется в Telegram-канал и VK группу
4. Сообщение обновляется при изменениях (добавлении/отмене записей)

### 1.5. Система записи пользователей
1. Пользователь выбирает тренировку из опубликованного расписания
2. Отправляет заявку на запись (статус "pending")
3. Администратор подтверждает или отклоняет заявку
4. При подтверждении расписание автоматически обновляется в каналах
